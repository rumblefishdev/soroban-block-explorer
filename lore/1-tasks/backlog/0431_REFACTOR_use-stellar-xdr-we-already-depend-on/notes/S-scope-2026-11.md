# Scope added 2026-11-18, and what stays out

## Added: indexer off our JSON dialect (stage 3 of 0363 decision 13)

The owner decided (rows 22–24 of the
[0363 S note](../../0363_FEATURE_advanced-scval-decoded-rendering/notes/S-events-table-value-rendering.md))
that our own contract-value JSON dialect leaves the database and the
indexer, in stages. 0572 stores events as raw XDR first. Then these
readers, which pattern-match our JSON, move to stellar-xdr types
(`ScVal` and its `scval_conversions`) one module per PR:
`pool_state.rs`, `pool_config_factory.rs`, `asset_transfers.rs`,
`executable_ref.rs`, the helpers in `scval.rs`.

Also here: the "adopt, 0431" findings of the second audit pass in
[R-audit-hand-rolled-decoding](../../0363_FEATURE_advanced-scval-decoded-rendering/notes/R-audit-hand-rolled-decoding-2026-11.md)
(asset code through `from_utf8_lossy`, strkey checked by length,
own WASM parser, `encode_xdr` returning `""`, five duplicate conversions).

## Out of scope

Replacing our parser with the CLI. The CLI is a process, not a library; at
13M ledgers, spawning one per transaction is not viable. We already link the
same crate — the goal is to _call more of it_, not to shell out.
