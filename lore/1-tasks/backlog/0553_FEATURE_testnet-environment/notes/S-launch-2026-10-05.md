# Launch — 2026-10-05 / 06

What was done to make testnet public, what was decided on the way, and what
surprised us. Times are UTC.

## Sequence

   testnet secrets. Indexer committed paused.
2. **Backfill from genesis**, operator laptop, write cert, into `testnet`:
   ledgers 2–4,991,999 from `v1.1/stellar/ledgers/testnet/2025-12-18`.
   Result: 4,991,998 rows, `max - min + 1 - uniqExact = 0` (no holes).

4. **Cloudflare zone** (company `dns-cloudformation` repo, `cloudflare/`): the

## Decisions

- **Backfill as a queue, not fixed ranges.** `seq … | xargs -P 8`, one
  64k partition per process: a worker that finishes takes the next partition.
  Ranges split by bytes left most workers idle while one ground on the heavy
  tail. Download time is bound by the file count (~64k objects per partition),
  not by bytes.
- **Cloudflare done like mainnet, in the zone owner's Terraform**, not clicked
  in the dashboard; the dashboard only verifies.
- **Managed WAF on testnet first.** It had never been switched on for mainnet:
  the flag stayed off after the nameserver move, and its ruleset id default was
  wrong (fixed in the zone repo). AWS WAF had been removed earlier on the
  assumption that Cloudflare covered it, so mainnet has run without a WAF since
  2026-07-27. Testnet first because it has no users yet; mainnet follows on
  2026-10-07 if testnet's Security Events show no false positives (task 0624).
- **Managed Challenge stays off.** On a JSON API it answers with an HTML page
  that `fetch()` and API-key clients cannot solve; Turnstile does the bot
  filtering for the SPA.
- **Both networks deploy together** — task 0603, widened: a production
  release also deploys testnet; the indexer pause leaves the deployed config;
  testnet may run ahead of production, never behind.
- **Catch-up by the indexer, not a second top-up backfill.** See below.

## Surprises

- **`backfill-runner` cannot fill the open partition.** It refuses a partition
  whose files are not all on S3 yet ("S3 archive lag … skipping"), and exits 0
  having written nothing. The top-up from 4,992,000 to the tip therefore wrote
  0 ledgers; the indexer catches up instead. Writing up to the last published
  file would make every reset faster (task 0625).
- **The resume commit `8e9fb5b0b` says "plus a top-up to the lake tip".** There
  was none (the previous point); the indexer did the catch-up.
- **A worktree's `target/` vanished mid-backfill** (2026-10-05 15:46), taking
  the release binary; the 17 queued partitions failed at start with "No such
  file", the running ones kept going from memory. Cause not found. The binary
  is now built into a target directory outside every worktree.
- **Browser zoom is per host**, so a reader at 80% on mainnet lands at 100% on
  testnet after switching. A consequence of one host per network, accepted.
- **Error-level log lines that are not errors.** "token events rejected by
  the asset_transfers decoder" and "soroban pool amount event skipped" are
  logged at `ERROR` on both networks; the ledger still persists and the error
  rate alarm stays OK.
