# Facts and peers for the shared session cookie

| #   | Fact                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Provenance                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | SPA and API are **same-site** (registrable domain `sorobanscan.com`; PSL has only `com`). A `SameSite=Strict` cookie is sent on the SPA's `fetch` to the API, also when the visitor arrived from another site. No third-party-cookie rule applies.                                                                                                                                                                                                                                                            | source: RFC 6265bis §2.3, §5.2, §4.1.2.7; measured: PSL grep                                                                                                                      |
| F2  | A host-only `__Host-` cookie on `api.sorobanscan.com` is never sent to `api-testnet.sorobanscan.com`: mainnet and testnet sessions stay apart.                                                                                                                                                                                                                                                                                                                                                                | source: RFC 6265bis §4.1.3.2                                                                                                                                                      |
| F3  | Credentialed CORS needs `Access-Control-Allow-Credentials: true` on the API Gateway preflight (CDK `allowCredentials`) and on the axum `CorsLayer`; origins stay an explicit list (tower-http 0.6.8 panics on a wildcard with credentials).                                                                                                                                                                                                                                                                   | source: Fetch §3.3.5; tower-http-0.6.8 `cors/mod.rs:783-808`; `aws-cdk-lib` `cors.d.ts:53`                                                                                        |
| F4  | Without `Authorization`, a `GET` with only `Accept` is a CORS simple request: no preflight. Only the JSON `POST /auth/session` stays preflighted.                                                                                                                                                                                                                                                                                                                                                             | source: Fetch, CORS-safelisted request header                                                                                                                                     |
| F5  | CSRF: reads are `GET` and change nothing; the mint is a JSON `POST` (preflighted against the origin list) that needs a valid Turnstile token. SameSite + the CORS list cover it. Residual risk: a taken-over `*.sorobanscan.com` subdomain is same-site.                                                                                                                                                                                                                                                      | source: OWASP CSRF Prevention CS (Fetch Metadata, SameSite Limitations)                                                                                                           |
| F6  | No edge cache serves gated responses today: Cloudflare answers `cf-cache-status: DYNAMIC` with no cache rules, the API Gateway cache is off. But responses carry `Cache-Control: public, max-age=…` with no `Vary`; a future Cloudflare cache rule would serve a session's 200 to a request with no session. Same with `Bearer` today: RFC 9111 §3.5 lets `public` be shared.                                                                                                                                 | source: `docs/architecture/backend/api-gateway-cache-spec.md`, task 0346, `crates/api/src/common/cache_control.rs:30-33`; soroban-infrastructure `cloudflare/` has no cache phase |
| F7  | x402 defines no session; a seller lets other credentials skip payment through its own hook (`onProtectedRequest` → `grantAccess`). Peer order: existing auth first, payment last. A cookie never pays; the paid branch stays header-only (`PAYMENT-SIGNATURE`), so it carries no CSRF risk. A browser reading `PAYMENT-REQUIRED` / `PAYMENT-RESPONSE` later needs `Access-Control-Expose-Headers`.                                                                                                            | source: coinbase/x402 `specs/transports-v2/http.md`, `@x402/core` 2.31.0 `http/index.js:915-950`; Polygon seller guide                                                            |
| F8  | JS cannot read an HttpOnly cookie, so a tab cannot see the expiry; the 401 is the signal. Peers: Cloudflare pre-clearance replays a `fetch` after `cf-mitigated: challenge`; Blockscout returns the TTL in a header.                                                                                                                                                                                                                                                                                          | source: RFC 6265bis §4.1.2.6; Cloudflare blog "integrating Turnstile with the WAF"; blockscout `api_key_controller.ex`@b89bc105                                                   |
| F9  | Hidden tabs do not poll (`refetchIntervalInBackground` unset, TanStack default `false`), so after an expiry usually only the visible tab gets a 401.                                                                                                                                                                                                                                                                                                                                                          | source: `web/src/api/QueryProvider.tsx`; TanStack Query v5 defaults                                                                                                               |
| F10 | Cargo.lock has no cookie crate; `axum-extra` (tokio-rs) with feature `cookie` parses `Cookie` and builds `Set-Cookie`. The hey-api client takes `credentials: 'include'` through `client.setConfig`.                                                                                                                                                                                                                                                                                                          | measured: `grep -i cookie Cargo.lock`; source: `libs/api-types/src/generated/client/client.gen.ts`                                                                                |
| F11 | Authenticated Origin Pulls: ADR 0048 Decision 3 chose zone-level AOP with our own client cert; never built. Dormant CDK mTLS needs `enableCloudflareApiDomain` (`infra/src/lib/types.ts:708`), which is off; direct `/health` probes and the origin-lock canary would break. The known hole is a regional API Gateway IP with SNI `api.sorobanscan.com`: `/health` 200, data 403 (ADR 0048, note 2026-11-17). Data behind it still needs a session or key. Estimate: 4–6 h first rollout + ~2 h per rotation. | source: ADR 0048; `api-gateway-stack.ts:195-208`; Cloudflare "protect your origin server"; estimate                                                                               |
| F12 | Neither logs nor metrics show mints, 401s, edge-lock 403s or visitors: the Lambda logs no per-request line, the stages have no access logs, metrics split only by API and stage. Production 2026-10-21..11-19: 32,883 requests (not 31,452), typically 450–1,700 a day, spike 9,932 on 11-15; 5XX 7 in 31 days; Turnstile warn lines 0 on both networks. Requests that never reach the Lambda (Count − Invocations, ~60–120 a day) match the OPTIONS preflights API Gateway answers itself.                   | measured 2026-11-19: CloudWatch AWS/ApiGateway Count/4XX/5XX, AWS/Lambda Invocations, Logs Insights (measurer agent); the preflight reading is derived                            |

Peers compared: Cloudflare Turnstile pre-clearance (`cf_clearance`,
`SameSite=None; Secure; Partitioned`, checked by a WAF rule; unproven for a
CloudFront page with a Cloudflare-proxied API); Blockscout `api_v2_temp_token`
(signed cookie, `SameSite=Lax`, no HttpOnly; selects a rate-limit bucket, not
a hard gate); the Prices portal session cookie (`SameSite=Lax`, same-site,
`docs/architecture/infrastructure/infrastructure-overview.md`). Etherscan and
Stellar explorers: not found.
