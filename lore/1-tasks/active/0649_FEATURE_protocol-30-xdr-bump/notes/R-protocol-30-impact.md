# Protocol 30: impact on the explorer

Inventory sources: stellar-core v30.0.0 release notes (three CAPs: 0084,
0087, 0088), the XDR core pins (stellar-xdr commit `4f524bba`), the CAP
texts, and what downstream consumers changed: stellar-horizon#237,
go-stellar-sdk#6015, stellar-rpc#1050, js-stellar-sdk#1811 (open). No
protocol-30 `ConfigSettingId` and no vote date were found (2026-10-19).

| #   | Change                                                                                                       | Touches us?                  | Where, and what to do                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `StellarValue` arms `SIGNED_MS`/`EMPTY_TX_SET_MS`, mandatory from the ledger after the upgrade (CAP-0088)    | **Yes — blocking**           | Every decode of a `LedgerCloseMeta`. `stellar-xdr` 28 fails on the first protocol-30 ledger. Fix: the bump. Gate test like `protocol_28_arms.rs`.                                                                                                                                                                                                                                                                                              |
| 2   | `closeTimeMs`; `closeTime` stays seconds; ledgers may share a second (CAP-0088)                              | No                           | `closed_at` reads `scp_value.close_time` (`xdr-parser/src/ledger.rs`). API `closed_at` predicates are ranges; no code computes time between ledgers. Not stored (no requester).                                                                                                                                                                                                                                                                |
| 3   | `ScAddress::MuxedContract`, `W…` strkey (CAP-0084)                                                           | **Yes**                      | Owner chose full support (task decision table). Places: `scval_to_typed_json`, `balance_key_holder`, `invocation.rs` call target, `op_source.rs` signer, `persist/value_flow.rs` `split_muxed`, `persist/stage.rs` + `contract_activity.rs` filters, API `common/path.rs`, `common/filters.rs`, `search/classifier.rs`, UI `libs/ui/src/identifiers/validators.ts` (`addressType` → `null` today, so a `W…` shows as unlinked text, no crash). |
| 4   | SAC `transfer` to a muxed contract: topics keep `C…`, data is `{amount, to_muxed_id}` (CAP-0084)             | **Yes**                      | Amount: already read by key (`asset_transfers.rs` `token_event_amount`). Muxed id: today `to_muxed_id` comes only from the topic (`M…`) or a classic op's destination (`value_flow.rs`), never from event data, so a transfer to `W…` would store `to_muxed_id = NULL`.                                                                                                                                                                        |
| 5   | `W…` banned in contract data keys, invoke targets, auth credentials (CAP-0084; host per js-stellar-sdk#1811) | No                           | Balances and contract state keep plain `C…` keys; the call-target path never sees `W…`.                                                                                                                                                                                                                                                                                                                                                        |
| 6   | ML-DSA host functions, `ContractCostType` 86–94 (CAP-0087)                                                   | No                           | We never decode cost types; config-setting entries are recorded as an id with an empty body (`ledger_entry_changes.rs`).                                                                                                                                                                                                                                                                                                                       |
| 7   | Spec name limit 60 → 1024, `ScSpecEventV0.name` becomes a string (stellar-xdr#312)                           | No                           | Wire-compatible; WASM spec reads compile unchanged; names are `String` columns.                                                                                                                                                                                                                                                                                                                                                                |
| 8   | `soroban-env-host` 30 runs only protocol-30 ledgers                                                          | **Yes**                      | `contract-executor` token metadata (`indexer/src/contract_metadata.rs`); decided: one host 30 that states its own protocol (task decision table).                                                                                                                                                                                                                                                                                              |
| 9   | Tx-set validity hardening, overlay minimum version, banned-accounts deprecation (core#5481, #5483, #5426)    | No                           | Validator behaviour, not ledger data.                                                                                                                                                                                                                                                                                                                                                                                                          |
