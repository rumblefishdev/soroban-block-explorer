## CH schema reality (from `crates/db-clickhouse/schema/init.sql`)

**Engine assignment:**

- Immutable lookups → `MergeTree`: `ledgers`, `liquidity_pools`, `wasm_interface_metadata`
- State tables → `ReplacingMergeTree(version_col?)`: `accounts` (`last_seen_ledger`), `assets` (no version — last-write-wins by ORDER BY), `account_balances_current` (`last_updated_ledger`), `soroban_contracts` (`wasm_uploaded_at_ledger`), `nfts` (`current_owner_ledger`), `lp_positions` (`last_updated_ledger`)
- Fact tables → `ReplacingMergeTree` (no version) partitioned by `intDiv(ledger_sequence, 500000)`: `transactions`, `transaction_hash_index`, `operations_appearances`, `transaction_participants`, `soroban_events`, `soroban_invocations_appearances`, `nft_ownership`, `liquidity_pool_snapshots`
- Dictionary: `transaction_hash_dict` over `transaction_hash_index`

**Implication for queries:** `FINAL` required on EVERY read except `ledgers`, `liquidity_pools`, `wasm_interface_metadata`. Partition predicate via `intDiv(ledger_sequence, 500000) BETWEEN intDiv(?, 500000) AND intDiv(?, 500000)` available on the 8 partitioned tables.

**Bloom filter:** `transactions.idx_tx_hash_bloom` (granularity 1, FPR 0.01) — secondary index for hash lookups within partitions when Dictionary miss.

## Translation rules (PG → CH primitives)

| PG                                                          | CH                                                                                                                                | Note                                                                                                                        |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `NOW()`                                                     | `now()`                                                                                                                           | lowercase                                                                                                                   |
| `INTERVAL '7 days'`                                         | `INTERVAL 7 DAY`                                                                                                                  | unquoted                                                                                                                    |
| `NOW() - INTERVAL '60 seconds'`                             | `now() - INTERVAL 60 SECOND`                                                                                                      |                                                                                                                             |
| `EXTRACT(EPOCH FROM (a - b))`                               | `dateDiff('second', b, a)`                                                                                                        | arg order flipped                                                                                                           |
| `::float8`                                                  | `toFloat64()`                                                                                                                     |                                                                                                                             |
| `::bigint`                                                  | `toInt64()`                                                                                                                       |                                                                                                                             |
| `::smallint`                                                | `toInt16()`                                                                                                                       |                                                                                                                             |
| `encode(b, 'hex')`                                          | `lower(hex(b))`                                                                                                                   | CH `hex()` returns UPPERCASE; PG returns lowercase                                                                          |
| `decode(s, 'hex')`                                          | `unhex(s)`                                                                                                                        |                                                                                                                             |
| `LATERAL (SELECT ... LIMIT 1)`                              | scalar subquery `(SELECT ... ORDER BY ... LIMIT 1)` OR `LIMIT 1 BY ...`                                                           | LATERAL supported since CH 23.x but scalar subquery is cleaner for 1-row joins                                              |
| `array_agg(DISTINCT x)`                                     | `groupUniqArray(x)`                                                                                                               |                                                                                                                             |
| `array_agg(x ORDER BY ...)`                                 | `groupArray(x)` w/ pre-sorted subquery OR `arraySort(...)` post-hoc                                                               |                                                                                                                             |
| `op_type_name(SMALLINT)` (PG fn)                            | omit; return raw SMALLINT, decode in API                                                                                          | CH has no equivalent function; we could define a dictionary for enums but defer (out of scope)                              |
| `pg_class.reltuples`                                        | `(SELECT count() FROM tbl FINAL)` OR `(SELECT total_rows FROM system.tables WHERE name = 'tbl')`                                  | CH `count()` is fast on columnar storage, but `system.tables.total_rows` is O(1) and matches the planner-estimate semantics |
| `WHERE created_at = $closed_at` partition prune             | `WHERE intDiv(ledger_sequence, 500000) = intDiv($ledger_seq, 500000)`                                                             | partition predicate must reference partition expression literally                                                           |
| composite FK `(tx_id, created_at)`                          | just `tx_id`                                                                                                                      | no created_at on CH fact tables                                                                                             |
| keyset cursor `(created_at, id) < ($cursor_at, $cursor_id)` | same syntax, but tuple becomes `(ledger_sequence, application_order, id)` since no created_at                                     |                                                                                                                             |
| `DATE_TRUNC('day', t)`                                      | `toStartOfDay(t)`                                                                                                                 | also `toStartOfHour`, `toStartOfFifteenMinutes`, etc.                                                                       |
| `LAG(x) OVER (ORDER BY ...)`                                | `lagInFrame(x)` w/ window frame OR `LAG(x)` (supported since CH 23.x)                                                             |                                                                                                                             |
| `LEAD(x) OVER (ORDER BY ...)`                               | `leadInFrame(x)` OR `LEAD(x)`                                                                                                     |                                                                                                                             |
| `pg_trgm` GIN index for `ILIKE '%q%'`                       | no equivalent — use `LIKE` (full scan) or `tokenbf_v1` skip index if defined                                                      | E22 affected; documented                                                                                                    |
| `JSONB` projection                                          | CH `String` projected verbatim (CH has `JSON` since 24.x but ADR 0044 keeps `metadata` as `String` for `wasm_interface_metadata`) |                                                                                                                             |
| `BYTEA`                                                     | `FixedString(N)` or `String`                                                                                                      | hash columns use `FixedString(32)`                                                                                          |

## Anti-patterns to reject in review

```sql
-- WRONG: full scan, ignores Dictionary
SELECT * FROM transactions WHERE hash = unhex('...');

-- WRONG: PG ON CONFLICT (CH uses Replacing merge semantics)
INSERT INTO ... ON CONFLICT (...) DO NOTHING;

-- WRONG: missing FINAL on state read
SELECT * FROM account_balances_current WHERE account_id = ?;
-- → returns dup rows pre-merge

-- WRONG: t.created_at on non-ledgers table (§5.2)
SELECT t.created_at FROM transactions t WHERE ...;
-- → column does not exist in CH

-- WRONG: JOIN to soroban_events_appearances (§5.1, table absent)
SELECT e.* FROM contract_events e
JOIN soroban_events_appearances ea ON ea.event_id = e.id;

-- WRONG: SELECT n.metadata FROM nfts (§5.3, column absent)

-- WRONG: pg_trgm operator (no CH equivalent)
SELECT * FROM assets WHERE name % 'usd';
-- → use LIKE '%usd%' (full scan) or tokenbf_v1 skip index
```

## Phase 2 skeleton seeded queries (every .sql will start with `SELECT 1`)

CI Tier 1 parse target: every file must `clickhouse-client --query="$(cat NN.sql)" --format=Null` exit 0 against canonical schema.

Composite parameter substitution pattern (mirrors PG `run_endpoint.sh`):

- `$1` = first positional arg (e.g. account StrKey, tx hash hex)
- `$2..` = subsequent (limit, cursor tuple)
- `:_var` = cross-statement bind from `\gset` (PG-only; CH equivalent is positional bind via shell)

## Discovery sources (for Phase 4 validation)

For each query the runner needs a real input:

- `transactions.hash` (32-byte hex) — `SELECT lower(hex(hash)) FROM transactions FINAL ORDER BY ledger_sequence DESC LIMIT 1;`
- `accounts.account_id` (G-StrKey) — `SELECT account_id FROM accounts FINAL ORDER BY id DESC LIMIT 1;`
- `soroban_contracts.contract_id` (C-StrKey) — same shape
- `assets.id` (Int32 surrogate) — same
- `nfts.id` (Int32 surrogate) — same
- `liquidity_pools.pool_id` (32-byte hex) — same w/ `lower(hex(pool_id))`
- `ledgers.sequence` — `SELECT max(sequence) FROM ledgers;`

All work against canonical CH; Phase 4 populates real data via `cargo run -p backfill-runner -- --target clickhouse --start S --end E`.

## Open questions resolved during Phase 1

1. **Does CH mirror at `ch-mirror-setup.sh` match canonical schema?** No — column types differ (`UInt64` vs `Int64`, `hash_hex FixedString(64)` vs `hash FixedString(32)`). **Decision:** target canonical `crates/db-clickhouse/schema/init.sql` via fresh `docker compose up clickhouse` not the local mirror.

2. **Does Phase 4 row-count diff against empty CH make sense?** No. Populate CH via `backfill-runner --target clickhouse` against a small ledger range (e.g. 62046000-62047000 already on audit PG) before Tier 2-4 validation.

3. **E14 — does CH version still need Archive overlay?** **No.** `soroban_events.topics_xdr` + `data_xdr` are inlined per §5.1. Major divergence vs PG E14 — document explicitly in header.

4. **E22 trigram — block task or defer?** Defer free-text path to follow-up task; ship E22 with `LIKE`-on-StrKey-prefix which is the same path PG's `run_endpoint.sh` already exercises. R3 in risk register.

5. **`op_type_name(SMALLINT)` PG fn — replicate in CH?** No; out of scope. Project raw SMALLINT and document that API decodes via Rust enum (same as PG today — `op_type_name` is a Postgres SQL helper, not the canonical source).

6. **Bloom filter `idx_tx_hash_bloom` on transactions — used by E04?** Not directly; the Dictionary `transaction_hash_dict` is the hot path. Bloom is fallback if Dict miss + scan; document but don't reference in query.
